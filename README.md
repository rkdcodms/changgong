창의공학설계 AutoRobot 팀 공유 저장소.

## 카메라 연동 오토로봇

동상 인식 후 5초 정지하는 라인트레이서와 Chrome 카메라 화면은 [autorobot 실행 안내](autorobot/README.md)에 있다. Jetson 코드, 화면 v3, Mega 펌웨어, 팀용 설정 예시를 함께 제공한다.

- 같은 Jetson에 Tailscale로 접속할 수 있는 팀원은 PC별 IP 등록 없이 영상에 접근하도록 설정할 수 있다.
- 설정 변경은 SSH에서 로컬 설정 파일을 수정하고 적용한다. 카메라 페이지는 영상과 상태를 표시한다.
- 카메라 연동 시험에는 `autorobot/arduino/vision_stop/vision_stop.ino`와 `autorobot/jetson`을 함께 사용한다.
- 공유 코드는 오프라인 검사를 통과했으며, 이번 팀 접속 설정은 실제 Jetson에 아직 적용하지 않았다.

## 라인트레이서 단독 코드

Arduino Mega 2560용 코드는 [line_tracer_ver3_updated.ino](arduino/line_tracer_ver3_updated/line_tracer_ver3_updated.ino)에 있다. 팀이 제공한 `line_tracer_ver3.ino`에서 모터 방향 핀 네 개와 정지 시간만 바꿨다. 기존 주행 로직, 센서 판정, 속도 설정은 유지했다. 소스 머리말의 `ver2` 표기도 원본에 있던 것이다.

**전원 투입 또는 RESET 후 자동으로 주행한다.** 별도 시작 버튼이나 Serial 시작 명령은 없다. USB 연결·Serial 열기로 보드가 재시작될 수도 있으므로, 처음 업로드하거나 검사할 때는 바퀴를 띄우고 모터 전원을 분리한다.

| 연결 | Mega 핀 |
|---|---|
| L298N ENA / ENB | D5 / D6 |
| L298N IN1 / IN2 / IN3 / IN4 | D30 / D31 / D32 / D33 |
| 뒤에서 전진 방향을 바라볼 때 센서 왼쪽 → 오른쪽 | A7, A6, A5, A4, A3, A2, A1, A0 |

핀 번호와 센서 순서는 사용자가 확인한 연결이다. 코드의 채널 A=왼쪽 모터, 채널 B=오른쪽 모터 가정과 각 모터의 전진 극성은 별도 실물 확인이 필요하다. ENA/ENB 점퍼와 전원 경로도 확인 대상으로 남긴다.

### 실행 방법

1. 이 저장소를 내려받고 `arduino/line_tracer_ver3_updated/line_tracer_ver3_updated.ino`를 Arduino IDE에서 연다. 폴더와 스케치 이름을 함께 유지한다.
2. 보드를 **Arduino Mega or Mega 2560**, 프로세서를 **ATmega2560**으로 선택하고 먼저 컴파일한다.
3. 실제 연결된 포트를 확인한다. 과거 PC 측정 포트는 COM3였지만 다른 PC나 Jetson에서도 같다고 가정하지 않는다.
4. 업로드가 필요하면 기존 프로그램 백업과 안전 상태를 확인한 후 진행한다. 업로드는 보드의 현재 프로그램을 교체한다.
5. Serial 모니터는 115200bps로 연다. 값 8개의 순서는 **A0 → A7**, 즉 로봇 오른쪽 → 왼쪽이다.

Arduino CLI로는 저장소 루트에서 다음 명령으로 컴파일할 수 있다.

```sh
arduino-cli compile --fqbn arduino:avr:mega arduino/line_tracer_ver3_updated
```

### 현재 동작

- `analogRead()` 값이 500 이하면 흰색, 초과면 검정으로 처리한다. OUT/GND/VCC 3핀 센서라는 사실과 A0~A7 연결만으로 아날로그 출력이라고 단정하지 않는다. 이 읽기 방식은 이번 변경에서 유지한 원본 로직이다.
- 흰색 선을 따라가며 코너에서 감속하고, 선을 놓치면 마지막 감지 방향으로 탐색한다.
- 8개 모두 흰색인 측정이 10ms 제어 주기에서 3회 연속이면 제동한다.
- **정지 시점부터 5초가 지나면 자동 재출발한다.** 미션 완료 여부를 확인하는 기능은 없다.
- 처음부터 모두 흰색이면 출발선으로 보고 빠져나온다. 정상 선을 다시 확인한 뒤 정지 감지를 재개한다.
- 탐색이나 정지선 탈출에 실패하면 `FAULT`로 멈춘다. 위치를 바로잡고 RESET하면 다시 시작한다.

### 확인한 범위

2026-11-09에 Arduino AVR Boards 1.8.8, `arduino:avr:mega` 대상으로 컴파일을 확인했다. 프로그램 8,984바이트, 전역 변수 296바이트다. 이 공유 작업에서는 보드 업로드나 모터 구동을 하지 않았다.

공유한 스케치는 요청한 핀 배치와 5초 재출발 동작을 가진 독립 주행판이다. 카메라 인식과 미션 제어를 연결한 완성 AutoRobot 펌웨어로 간주하지 않는다.

## 기존 자료와 현재 코드의 관계

이번 공유 전 `main`의 `e35b3df`에는 제목만 있는 README와 Word·PDF 문서가 있었고, 별도의 `.ino`·`.py` 실행 소스는 없었다.

- `Team 1 Pre Report_Part4 작성.docx`는 자동 로봇의 IR 라인트레이싱·카메라 인식 구상, 수동 로봇의 제작·시험 기록, YOLO11n 학습 계획을 담고 있다. 조각상 8종, 사진 20,000장, 학습·검증 분할과 학습 설정은 계획으로 서술되어 있으며, 학습된 모델·실행 코드·성능 결과가 첨부되어 있지는 않다.
- `로보콘 설명 및 조립 안내.pdf`는 조립·부품·배선 설계 자료다. PDF 25쪽에 현재 설계용 실행 프로그램이 아직 완성되지 않았다고 명시되어 있다. 24·55쪽의 센서 AO/DO 및 좌우 배열 설명은 최신 확인과 다르므로 적용하지 않는다. 전원 경로와 부품 배정도 최신 실물 확인값으로 간주하지 않으며, 최신 사용자 확인과 실물 측정을 우선한다.

기존 문서의 설계 설명만으로 카메라와 주행이 이미 연결됐다고 판단할 수 없다. 팀원의 실제 실행 소스와 모델 파일이 있다면 별도로 공유해야 한다.

## 팀 통합 때 보충할 것

1. **Jetson과 Mega의 명령 연결** — 현재 Serial은 센서값 출력만 한다. 시작·정지·다음 목표 명령 수신, 응답, 통신 끊김 시 정지 동작을 별도 통합판에 구현하고 양쪽에서 검증해야 한다.
2. **카메라와 시련 상태 관리** — 조각상 인식 모델, 시련 순서, 목표 표식 선택, 완료 판정, 출발 공간 확인, 마지막 시련 종료 처리가 필요하다. 현재 5초 타이머를 미션 완료 신호로 취급하면 안 된다.
3. **실물에서 주행 조건 확정** — 모터 채널의 좌우, 전진 극성, 최소 구동 PWM, 센서 높이와 흑백 반응, 실제 정지 위치를 순서대로 확인한다. 소스의 바퀴 지름 6.5cm·윤거 19cm·센서 전방 거리 5cm·회전주기 0.448초는 기존 가정이며 실측 확정값이 아니다.
4. **팀원이 재현할 자료** — Jetson 실행 파일과 환경·모델 파일 위치, 확인된 배선표, 테스트 조건과 결과를 함께 저장한다. 각자의 최신 실행 코드를 문서 속 예제와 구분한다.

현재 독립 주행판의 5초 재출발 동작은 유지하고, 카메라·미션 통합 변경은 별도 브랜치에서 검토한다.
