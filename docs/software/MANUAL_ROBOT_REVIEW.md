# 수동 로봇(텔레오퍼레이션) 코드 검토 — 2026-11-12

대상: main `e7ff2d7`의 `teleoperation /Leader_Grip_Track.ino`, `teleoperation /Follower_Grip_Track.ino` (폴더명 끝에 공백 1칸). 이 검토는 **소스 읽기만** 했다. 컴파일(Dynamixel2Arduino·OpenRB-150 코어 필요)과 실물 구동은 하지 않았고 코드도 바꾸지 않았다.

## 1. 소스가 가정하는 구성

| 보드 | 역할 | 통신 |
|---|---|---|
| OpenRB-150 리더 | 사람이 움직이는 팔. 부팅 시 3초간 2048로 이동 후 토크 OFF, 측정 자세를 40Hz로 송신 | BT `Serial2` 57600, `p1,p2,p3,p4,gripper_delta\n` |
| OpenRB-150 팔로워 | 실제 로봇 팔 + 바퀴 | BT 수신, RC 수신기 PPM(D0), DXL 1Mbps Protocol 2.0 |

|---|---|---|---|---|---|---|

| p2 (어깨, 쌍 관절) | 2 | 2 + 6 (6은 Drive Mode 역방향) | XL430-W250 | 위치 | 각각 540..3329, 영점 2048, 리더→팔로워 부호 −1 | **예** (모델번호 1060) |

## 2. 이전 설계 요구(손목·그리퍼 XL330)와의 차이 — **실물 확인 필요**

- 소스는 그리퍼를 XC330으로 적고 있고, 손목(p4, ID4) 모델은 적혀 있지 않다. 이전 요청은 손목 틸트·그리퍼 모두 XL330이다. 소스의 주석만으로 실물을 확정할 수 없다.
- **전압이 가장 위험하다.** XL430은 보통 11.1~12V 버스에서 쓴다. XL330 전체와 XC330의 M 계열(M077/M181/M288)은 5V급 모터다(XC330 T 계열은 12V급). 5V급 모터를 XL430과 같은 12V 버스 배선에 연결하면 모터가 손상될 수 있다. 실제 모델 라벨과 전원 배선을 확인하기 전에는 전원을 넣지 않는다.
- 전류 단위·한계, 위치 분해능, 최대 토크가 모델마다 다르다. 그리퍼 전류 700 raw, 호밍 500 raw는 "원래 XC330 값"이라는 주석만 있다. XL330으로 바뀌었다면 같은 raw 값이 같은 힘을 뜻한다고 가정하지 않는다.
- 활을 집어 **회전시켜** 오디세우스에 붙이려면 손목 롤(회전) 축이 필요한지 기구 설계를 확인해야 한다. 현재 소스의 관절은 베이스·어깨·팔꿈치·손목(p4)·그리퍼 5개이며, p4가 틸트인지 롤인지 소스에서 알 수 없다.

현장에서 기록할 값 (Dynamixel Wizard 2.0, **토크 OFF, 팔을 손으로 받친 상태**에서 읽기만):

| ID | 모델명/번호 | 펌웨어 | 버스 전압(Present Input Voltage) | Drive Mode | Operating Mode | Homing Offset | Min/Max Position Limit | Current/PWM Limit | 기준 자세 raw |
|---|---|---|---|---|---|---|---|---|---|
| 1~6, 9, 10 | | | | | | | | | |

리더 1~5도 같은 표로 기록한다. 값이 확인되면 그 값을 기준으로 코드 상수를 고치는 별도 PR을 만든다. 확인 전에는 소스의 값을 "현재 실물의 안전 한계"라고 쓰지 않는다.

## 3. 통신 끊김·시작 자세·방지턱에서의 동작 (소스 기준)

| 상황 | 소스 동작 | 경기 영향·시험 항목 |
|---|---|---|
| BT 끊김 500ms | 팔은 **측정된 현재 자세를 토크 ON으로 유지** | 들고 있던 물체는 유지. 재연결되면 프로파일 속도로 리더 자세를 다시 따라가므로, 리더를 비슷한 자세에 두고 재연결 |
| RC(PPM) 끊김 150ms | 바퀴 정지, 중립 25회(약 0.5초) 확인 후 재무장 | 경사로 위에서 끊기면 미끄러지는지 시험 |
| 쌍 관절 부하·동기·온도 초과 | **전체 토크 OFF 래치** → 팔이 떨어짐, 전원 재투입(=리셋 −5점) | 16mm 방지턱·경사로 충격에서 부하 45%/동기 60 raw를 넘는지 가장 먼저 시험 |
| 그리퍼 통신·오류 | 그리퍼만 토크 OFF (팔은 유지) | **잡고 있던 활·핀을 놓친다.** 방지턱 주행 중 그리퍼 오류 여부 기록 |
| 부팅 | 팔로워: 2048(쌍 관절은 영점)로 천천히 이동(최대 15초) 후 그리퍼 접촉 호밍(최대 4초) / 리더: 3초 2048 이동 후 토크 OFF | 시작 자세가 크기 측정(룰북 29쪽)과 부딪히지 않는지, 호밍 중 그리퍼가 물체를 집고 있지 않은지 |
| USB `!` | 소프트웨어 래치 정지 | 물리 비상정지가 아님 |

## 4. 활·핀 작업 시험 (흰색 자석 2개 / 유색 1개 두 버전 모두)

1. 바닥에 놓인 활(두께 5mm)·핀을 각각 10회 집기: 성공 수, 미끄러짐, 그리퍼 전류·과부하 오류.
2. 집은 채 16mm 경사로·방지턱 왕복: 낙하 수, 팔로워 래치 여부(`[LATCHED]` 사유 기록).
3. 회전·자석 부착: 부착 성공 수, 소요 시간, 오디세우스가 넘어지는지.
4. 각 시도를 `autorobot/tools/field_log.py add task --task bow_pick --seconds ...` 형식으로 기록하고, 실패 원인은 `--note`에 쓴다.
