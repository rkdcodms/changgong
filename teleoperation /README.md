# Teleoperation (Leader / Follower)

Leader 팔을 사람이 손으로 움직이면 관절 각도가 블루투스로 Follower에 전달되고, Follower 팔이 따라 움직인다. 바퀴는 별도의 RC 조종기(PPM)로 움직인다.

- **보드**: 둘 다 OpenRB-150, Dynamixel 버스 1 Mbps, 블루투스 57600 bps
- **통신 형식**: `p1,p2,p3,p4,gripper_delta\n` (값 5개, 25 ms마다 = 40 Hz)
- **그리퍼 값**: Leader 그리퍼 위치에서 2048을 뺀 값. 이번 프레임에 그리퍼 값이 없으면 `INT32_MIN`을 보내고, Follower는 직전 목표를 유지한다.

## Leader (`Leader_Grip_Track.ino`)

모터 ID 1~5를 쓰고, ID5가 그리퍼다.

1. **부팅 설정**: 각 모터를 ping하고 토크를 끈 뒤 동작 모드를 맞춘다. ID1~4는 위치 제어, ID5는 전류 기반 위치 제어.
2. **초기 자세 이동**: 토크를 켜고 모든 관절을 2048로 천천히 보낸다(속도 50, PWM 상한 약 50%). 3초 기다린 뒤 도착 여부와 관계없이 토크를 끈다.
3. **스트리밍**: 토크가 꺼진 상태에서 25 ms마다 5개 모터의 토크 상태, 하드웨어 에러, 위치를 한 번에 읽어 블루투스로 보낸다.
4. **프레임을 보내지 않는 경우**: 필수 모터(ID1~4) 응답이 빠졌거나 위치가 0~4095를 벗어나면 그 프레임만 버린다.
5. **래치(전송 영구 중단)**: 하드웨어 에러, 예상과 다른 토크 상태, USB로 `!` 입력, 블루투스 송신 실패 시 토크를 끄고 멈춘다. 전원을 껐다 켜야 풀린다.
6. **그리퍼는 선택 사항**: ID5가 없거나 고장 나면 그리퍼만 끄고 나머지는 계속 동작한다. 일시적인 응답 누락은 그 프레임만 `INT32_MIN`으로 보낸다.

## Follower (`Follower_Grip_Track.ino`)

팔 모터 ID 1~6, 바퀴 ID 9/10을 쓴다. 관절 2는 XL430 두 개(ID2와 ID6)가 1:1로 묶여 함께 움직이고, ID5가 그리퍼다.

1. **부팅 설정**: 모터를 찾고(최대 1초), 페어가 XL430인지 확인하고, 동작 모드·방향·위치 한계(540~3329)·PWM 상한을 설정한다. 현재 위치를 목표로 미리 넣은 뒤 토크를 켠다.
2. **초기 자세 이동**: 팔을 2048로 20 ms당 최대 6씩 천천히 옮긴다. 최소 3초, 최대 15초이며 오차 25 이내로 3회 연속 확인되면 완료.
3. **그리퍼 영점 찾기**: 닫는 방향으로 밀다가 위치가 멈추면 그 지점을 "닫힘"으로 기록한다(최대 4초).
4. **Leader 따라가기**
   - 관절 1·3·4: 받은 값을 범위 안으로 잘라 바로 목표로 쓴다.
   - 관절 2(페어): Leader 값을 부호 반전해 공통 좌표 q로 바꾸고, 20 ms당 최대 60씩 따라간다. ID2와 ID6에 같은 q를 준다.
   - 그리퍼: Leader 그리퍼가 움직인 범위를 학습해 "닫힘에서 얼마나 열렸는지"로 환산한다(최대 3684).
5. **블루투스 끊김**: 500 ms 동안 프레임이 없으면 현재 측정 위치에서 정지해 토크를 유지한다. 다시 들어오면 이어서 따라간다.
6. **바퀴**: PPM 채널 1(회전)과 3(전후진)을 20 ms마다 읽는다. 스틱이 중립인 상태가 25회 연속 확인돼야 구동이 켜지고, 신호가 150 ms 끊기면 정지한다.
7. **안전 감시**: 아래 조건에 걸리면 전체 토크를 끄고 래치한다. 전원을 껐다 켜야 풀린다.

| 대상 | 조건 |
|---|---|
| 페어 온도 | 65 °C 이상 |
| 페어 위치 | 540~3329 벗어남 |
| 페어 어긋남 | 180 초과 즉시, 60 초과가 120 ms 지속 |
| 페어 부하 | 45% 이상이 200 ms 지속 |
| 페어 추종 오차 | 180 초과가 1초 지속 |
| 페어 통신 | 읽기 3회 연속 실패, 토크 꺼짐, 워치독 발동 |
| 관절 1·3·4 | 하드웨어 에러 또는 토크 꺼짐 |
| 바퀴 | 명령 쓰기 실패 |
| USB | `!` 입력 |

   그리퍼(ID5) 문제는 그리퍼만 끄고 팔은 계속 동작한다. 바퀴가 부팅 때 없으면 바퀴만 빼고 팔은 동작한다.

8. **캘리브레이션 모드**: `CALIBRATION_MODE = true`로 올리면 모든 토크를 끈 채 ID2/ID6 위치만 0.5초마다 출력한다. 손으로 움직여 한계값을 잴 때 쓴다.

## 두 파일에서 같이 맞춰야 하는 설정

한쪽만 바꾸면 어긋난다.

| 항목 | Leader | Follower |
|---|---|---|
| 관절 2 영점 | `LEADER_J2_ZERO_RAW`, `FOLLOWER_J2_REFERENCE` = 2048 | `LEADER_J2_ZERO` = 2048 |
| 관절 2 방향 | `LEADER_J2_SIGN` = +1 | `LEADER_TO_FOLLOWER_J2_SIGN` = −1 |
| 그리퍼 기준 | `GRIPPER_REFERENCE_RAW` = 2048 | `GRIP_SPAN` = 3704, `GRIP_CLOSE_DIR` = +1 |
| 블루투스 속도 | 57600 | 57600 |

## 컴파일

Arduino IDE와 arduino-cli는 `.ino`와 이름이 같은 폴더를 요구한다. 이 폴더에는 두 스케치가 같이 있으므로, 각 파일을 같은 이름의 폴더로 복사한 뒤 연다.

```sh
arduino-cli compile --fqbn OpenRB-150:samd:OpenRB-150 Leader_Grip_Track
arduino-cli compile --fqbn OpenRB-150:samd:OpenRB-150 Follower_Grip_Track
```

보드 매니저 URL은 `https://raw.githubusercontent.com/ROBOTIS-GIT/OpenRB-150/master/package_openrb_index.json`, 라이브러리는 Dynamixel2Arduino다.

## 2026-11-16 코드 정리 (`refactor/teleop-cleanup`)

알고리즘, 상수, 통신 형식, 디버그 출력은 바꾸지 않고 중복만 줄였다.

- **Follower** (1378 → 1357줄): Sync Write 패킷 조립, USB `!` 정지 폴링, 단일 회전 보정, 페어 정렬 계산을 각각 함수 하나로 통합. 안 쓰는 변수 제거.
- **Leader** (631 → 629줄): 안 쓰는 `homeStart[]` 제거, 범위 검사·최솟값 헬퍼 도입, `loop()`에서 USB 폴링과 상태 출력 분리.
- **버스 통신이 달라진 곳은 한 군데**: Follower `configureArmMotor`에서 ID2/ID6의 `HOMING_OFFSET`을 읽고 쓰지 않던 중복 읽기를 뺐다. 같은 값을 같은 함수 뒤쪽에서 다시 읽는다.

검증한 것:

- OpenRB-150용 컴파일 통과(Dynamixel2Arduino 0.8.2, 오류·경고 없음).
- 모의 Dynamixel 버스에서 원본과 수정본의 모든 버스 호출, Serial/Bluetooth 출력, 타이밍 비교: 40개 시나리오 일치.

**실제 보드 업로드와 실물 동작은 확인하지 않았다.** 업로드할 때는 바퀴를 띄우고 팔을 받친 상태에서 먼저 확인한다.

### 리뷰에서 나온 확인 필요 사항 (코드는 그대로 둠)

1. `PAIR_FOLLOW_STEP_RAW = 60` 옆 주석이 "12 pulses per 20 ms"로 값과 다르다.
2. 바퀴 명령 쓰기가 한 번(5 ms 타임아웃) 실패하면 팔까지 포함해 전체 토크 OFF로 래치된다.
3. 관절 1·3·4는 속도 제한 없이 Leader 값으로 바로 이동한다. 블루투스가 끊겼다 돌아오면 한 번에 움직인다.
4. 폴더 이름 `teleoperation ` 끝에 공백이 있어 Windows에서 clone이 실패한다.
5. Leader의 `receivedCount < GRIPPER_INDEX` 검사는 그리퍼가 마지막 모터일 때만 맞다.
6. 페어 읽기 타임아웃 폴트는 실패 상세를 남기지 않고, `itemName`에 `GOAL_VELOCITY`가 없어 바퀴 폴트가 `CONTROL_ITEM`으로 찍힌다.
